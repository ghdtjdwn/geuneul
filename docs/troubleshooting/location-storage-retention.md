# 브라우저 위치 좌표 지속 저장 제거

- 날짜: 2026-09-02
- 상태: 코드 수정 및 로컬 검증 완료, 배포 확인 대기
- 영향 컴포넌트: `frontend/lib/context/geo.tsx`

## 맥락과 기대 동작

지도, 제보, 급해요 화면은 사용자가 허용한 현재 위치를 같은 브라우저 세션에서 공유한다. 정확한 위도·경도와 정확도는 기능 수행 중 메모리에만 있어야 하며, 페이지를 닫은 뒤 브라우저 저장소에 남지 않아야 한다.

## 실제 동작과 영향

`GeoProvider`는 마지막 위도·경도·정확도와 저장 시각을 `geuneul:last-location:v1` 키로 `localStorage`에 기록하고 7일 동안 복원했다. 이 값은 서버로 별도 업로드되지는 않았지만, 같은 오리진에서 실행되는 스크립트와 공용 단말의 브라우저 프로필에서 페이지 종료 후에도 읽을 수 있었다. 좌표가 외부로 유출됐다는 증거는 확인되지 않았다.

## 재현과 근거

1. 위치 권한을 허용하고 현재 위치 기능을 실행한다.
2. 개발자 도구의 Application → Local Storage에서 `geuneul:last-location:v1`을 확인한다.
3. 새 탭을 열면 저장된 좌표가 다시 초기 상태로 사용된다.

CodeQL의 clear-text local storage 경고와 실제 source를 대조해 정확한 좌표가 JSON으로 지속 저장되는 경로를 확인했다.

## 원인과 검토한 대안

첫 화면의 위치 복원과 권한 재요청 감소를 하나의 장기 캐시로 해결하면서 위치정보의 민감도보다 편의성을 우선한 것이 원인이다.

- `sessionStorage`: 탭 생명주기 동안에도 불필요한 지속 저장 표면을 만든다.
- 클라이언트 암호화: 복호화 키도 같은 오리진 코드가 가져야 하므로 XSS 경계에서 보호가 되지 않는다.
- 좌표 정밀도 축소 후 저장: 일부 기능은 정확한 현재 위치가 필요하고, 복원 좌표의 최신성도 보장하지 못한다.

## 해결

- 좌표와 정확도는 React 메모리 상태에서만 공유한다.
- 재사용은 브라우저 Geolocation API의 `maximumAge`에 맡긴다.
- 첫 `GeoProvider` mount에서 기존 `geuneul:last-location:v1` 키를 삭제한다.
- CI에 source 계약 검사를 추가해 위치 context의 storage read/write와 직렬화 캐시가 다시 들어오면 실패하게 한다.

## 남은 위험

- 기존 값을 가진 사용자는 수정 버전의 페이지를 다시 열어야 키가 삭제된다.
- 현재 위치를 사용하는 API 요청에는 기능 수행에 필요한 좌표가 전송된다. 전송 최소화와 서버 보관 정책은 별도 경계다.
- 같은 오리진 스크립트가 실행 중 메모리와 API 요청을 읽을 수 있는 XSS 위험은 CSP, 의존성 관리와 입력 방어로 계속 줄여야 한다.
